# to2610-smp 流片说明

流片说明报告（docx）的功能描述、寄存器含义、板级连接、测试说明与局限从这里取，只写在这一处。

## 功能描述

对称双核的 Linux 系统芯片，面向 ECOS 2610 班车。它是 `to2610-amp` 那一颗（`to2610-soc` 加第二个 KianV 核、第二个 CLINT、总线仲裁与核间的一页寄存器）改成两个核地位相同：各有编号，从同一个入口进同一份程序，原子指令在两个核之间成立。第二个核没放开时，整颗与 `to2610-soc` 一样，同一份镜像照样起得来。

KianV 的核是为单核写的，撑两个核差三处：`mhartid` 写死为 0；LR 只置一位预留、不带地址，SC 只看这一位；AMO 在总线上是先读后写两次访问，中间隔三拍。本仓自己写的有两样：`patch/smp.patch` 给核加编号、把原子指令的三个状态引出来、让第二个核从 SDRAM 起（八个文件，一百来行）；`hwsrc/smp_arb.v` 是管锁与预留的总线仲裁。核的子模块不动。

### 功能一览

| 项 | 支持 | 说明 |
|:--:|:--:|:--:|
| 处理器 | 两个 KianV 核，RV32IMA、Sv32 | `mhartid` 分别是 0 与 1，各有自己的 TLB |
| 存储与外设 | 同 `to2610-soc` | 片外 SDRAM 32 MiB 与 SPI Flash，原有的五个外设加窗里的十五个，两个核都看得见 |
| 总线 | 一条，两个核共用 | 一次访问做完才换人，换人之前空三拍；两边都在要就一人一次轮着来 |
| AMO | 读与写之间总线不换人 | 九条 AMO 指令都是原子的 |
| LR 与 SC | 预留按字记，每个核一条；另一个核写了同一个字就作废 | SC 写的不是预留的那个字也写不成 |
| 核间中断与计时器 | 每个核一个 CLINT：`0x0200_0000` 与 `0x0300_0000` | 两边的 `mtime` 是同一个计数，每微秒走一格 |
| 外部中断 | PLIC 只进第一个核 | 第二个核的机器态外部中断接核间那一页的门铃 |
| 第二个核的起停 | 核间那一页的 `RUN` | 复位后不动；放开后从 `0x8000_0000` 起 |

### 两个核怎么起

复位后只有第一个核在跑，启动流程同 `to2610-kvc`：从 Flash 的 `0x2010_0000` 就地执行引导程序，它把载荷搬进 SDRAM 再跳到 `0x8000_0000`。往 `0x4004_0004` 写 1 放开第二个核，它的复位地址也是 `0x8000_0000`，所以两个核进的是同一个入口；程序开头读 `mhartid`，按编号分栈、分路。放开要等载荷已经在 SDRAM 里之后再做，由引导程序、SBI 固件或载荷自己来写这一位都可以。

往 `RUN` 写 0 收回第二个核：它手上那一次总线访问做完之后才进复位，不会把半截访问留在总线上。再写 1，它从头来。

### 原子指令在两个核下怎么成立

成败都在总线仲裁这一处裁决，依据是核引出来的三个状态。

- AMO：核走到 AMO 的读那一拍起、写做完为止，仲裁不把总线给另一个核。半路进了异常，锁跟着状态一起落下。
- LR：仲裁记下这个核读的是哪个字。另一个核写了同一个字（普通的写、AMO 的写、写成了的 SC 都算），这条预留作废。
- SC：轮到它写的那一拍，预留已经作废或者地址不是预留的那个字，这一笔写不上总线，仲裁回给核一根「没写成」，核照写不成的路走（目的寄存器得 1）。核里原有的那一位预留只管试不试。

因为判与写是同一拍的事，不存在「核里查过了预留、写之前又被另一个核改了」的窗口。

## 寄存器

`to2610-soc` 的地址图原样保留（见它的流片说明）。这一颗新加的：

| 地址 | 含义 |
|:--:|:--:|
| `0x0300_0000` | 第二个核的 `msip`：第 0 位写 1，它收到机器态软件中断 |
| `0x0300_4000` | 第二个核的 `mtimecmp`，64 位，低字在前 |
| `0x0300_BFF8` | `mtime`，只读，与 `0x0200_BFF8` 是同一个计数 |
| `0x4004_0000` | 核间那一页的标识，只读，`0x534D5031`（"SMP1"） |
| `0x4004_0004` | `RUN`：第 0 位放开第二个核，复位为 0 |
| `0x4004_0008` | `BELL_A`：写 1 的位置起，读回挂着的；挂着就经 PLIC 的 26 号报给第一个核 |
| `0x4004_000C` | `ACK_A`：写 1 的位把 `BELL_A` 清掉 |
| `0x4004_0010` | `BELL_B`：同上，挂着就是第二个核的机器态外部中断 |
| `0x4004_0014` | `ACK_B`：写 1 的位把 `BELL_B` 清掉 |
| `0x4004_0018` | `MSG_A`：一个字，约定由第二个核写给第一个核 |
| `0x4004_001C` | `MSG_B`：一个字，约定由第一个核写给第二个核 |

第一个核的 `msip` 在 `0x0200_0000`，两个核互发核间中断就是往对方的这一位写 1。

## 板级连接

引脚与 `to2610-soc` 逐位相同，soc、amp、smp 三颗用同一块底板：payload 的前 54 位是 `to2610-kvc` 的那一组（串口 0、Flash、SDRAM、SD 卡口、SPI 网卡口、1 位 GPIO），余下 12 位（payload 第 54 至 65 位，下面叫 x0 至 x11）每位四选一，由 `0x4003_0004` 的 `PADSEL` 逐根选。

| 焊盘 | payload 位 | 0（复位） | 1 | 2 | 3 |
|:--:|:--:|:--:|:--:|:--:|:--:|
| x0 | 54 | GPIO 0 | 串口 1 TXD | RMII TXD0 | SPI 2 SCK |
| x1 | 55 | GPIO 1 | 串口 1 RXD | RMII TXD1 | SPI 2 CS0_N |
| x2 | 56 | GPIO 2 | 串口 1 RTS_N | RMII TX_EN | SPI 2 MOSI |
| x3 | 57 | GPIO 3 | 串口 1 CTS_N | RMII RXD0 | SPI 2 MISO |
| x4 | 58 | GPIO 4 | I2C SCL | RMII RXD1 | SerDes TX |
| x5 | 59 | GPIO 5 | I2C SDA | RMII CRS_DV | SerDes RX |
| x6 | 60 | GPIO 6 | 单总线 | RMII RX_ER | SPI 2 CS1_N |
| x7 | 61 | GPIO 7 | CAN TX | PWM 0 | I2S SCK |
| x8 | 62 | GPIO 8 | CAN RX | PWM 1 | I2S WS |
| x9 | 63 | GPIO 9 | PS/2 时钟 | PWM 2 | I2S SD 出 |
| x10 | 64 | GPIO 10 | PS/2 数据 | PWM 3 | I2S SD 入 |
| x11 | 65 | GPIO 11 | 计时器捕获 0 | 看门狗复位出 | 随机源入 |

payload 第 n 位是 MPC-Frame 的 `user_io[n + 7]`；逐位的完整位表在报告的「payload 位表」里。各组外设在板上怎么接（时钟同源、RMII 的 PHY、开漏脚的上拉、CAN 的收发器）见 `to2610-soc` 的流片说明。

- 时钟 50 MHz，两个核同一个时钟。
- 串口 0 是默认的调试输出与控制台，115200；第二个核没有自己的串口，要说话经核间那一页由第一个核转。
- 复位：按住复位时全部 payload 脚高阻，烧录器夹上 Flash 就能在板写。

## 测试说明

整片测试的测试台 `tb.cpp` 来自黑盒仓，跑在 Verilator 上，带 SDRAM、Flash、串口的引脚级模型；被测的是 `ran asic` 出的那份交付文件。仲裁另有一个单独的测试台。

| 用例 | 测什么 |
|:--:|:--:|
| arb | 仲裁单独测：两个假的核、一个应答晚若干拍的假从设备。换人之前空够三拍、对面在等时不连着用；两边各做四十次 AMO、四十次带重试的 LR 与 SC，一个不丢，而且确实有过写不成的；五条定向（没预留的 SC、写错字的 SC、对面写了同一个字、对面写了别的字、一边写成后另一边作废）；访问到一半收回第二个核 |
| arb 的七处埋错 | 逐个把仲裁里的一条规矩改掉（锁、轮转、SC 的裁决、跨核作废、地址比较、空拍、收回），每一处测试都要红；埋了错还过算这一项不过 |
| hello、periph、isa、boot | `to2610-kvc` 的四段原样再跑：第二个核没放开时，原有的通路与核的行为不许变。isa 里 `rv32ua` 那一组走的已经是新的仲裁 |
| xio | `to2610-soc` 的外设测试原样再跑 |
| smp：编号 | 第一个核读 `mhartid` 得 0；放开第二个核，它从同一个入口进来，报回的是 1 |
| smp：一个核时的 SC | 有预留写得成；没预留写不成、存储不变；预留的是另一个字也写不成，而且这一次把预留用掉了 |
| smp：直接加 | 两个核各把同一个数读出来加一再写回两百次，结果必须少于四百（仿真里是 295）。不丢数说明两个核没有真的在抢，下面三项就什么也证明不了。两个核跑的是同一段循环，步子一样会一直错开，所以每圈垫的指令数两边不同 |
| smp：`amoadd` | 两个核各加两百次，得四百 |
| smp：自旋锁 | 用 `amoswap` 抢锁，锁里读、隔几条指令、写回，两个核各两百次，得四百，锁最后是放开的；等锁的次数不能是零（仿真里 443 次） |
| smp：LR 与 SC | 带重试的加一，两个核各两百次，得四百；写不成重来的次数不能是零（仿真里 36 次） |
| smp：预留跨核作废 | 第一个核 LR 之后让第二个核写同一个字，SC 写不成，存储里是第二个核写的数；让它写别的字，SC 照样写成 |
| smp：核间中断 | 两个方向各发一次，各自进机器态软件中断、清掉对方写的那一位 |
| smp：第二个核的计时器 | 它设自己的 `mtimecmp`，中断来一次 |
| smp：收回与再放开 | `RUN` 写 0 之后第二个核的计数不再走；再写 1，它从头来、再报一次编号 |

## 局限

- 同 `to2610-kvc` 与 `to2610-soc` 的各条：缓存旁路、主频固定 50 MHz、没有 JTAG、核与规范不符的几处、外设在整片上测到哪一步。
- 两个核轮着用一条总线，都在忙时各自比单核慢一半上下。
- 外部中断只进第一个核；PLIC 没有第二个核的上下文。
- 预留按字记，一个核一条。开着虚存时取页表的读也会改写它，随后那一次真正的读再盖回来；LR 在取页表之后缺页的话，留下的是页表项的地址，随后的 SC 写不成。
- 第二个核的复位地址固定是 `0x8000_0000`，放开它之前那里要已经有程序。
- Linux 的双核启动还没有做：SBI 固件要认两个 CLINT，设备树要写两个核，核里软件写 `sip.SSIP` 的那处毛病要先修。这一颗目前验到裸机的两个核。
